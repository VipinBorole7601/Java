Java Selenium + TestNG Automation Framework Plan (From Scratch)
Repository: Git-based workflow
Build Tool: Maven
CI/CD: GitHub Actions (primary), adaptable to Jenkins/GitLab CI

1) Goal
- Build a scalable UI test automation framework using Selenium + TestNG with clear layers:
  test data -> test cases -> page objects -> reusable utilities -> reporting -> CI/CD.
- Support local execution, PR validation, nightly regression, and release-quality reporting.

2) Recommended Tech Stack
- Java: 17
- Build: Maven
- Test runner: TestNG
- UI automation: Selenium WebDriver 4.x
- WebDriver binaries: WebDriverManager
- Logging: SLF4J + Logback
- Assertions: TestNG Assert (optionally AssertJ)
- Reporting: Allure + Surefire reports
- Config: .properties + environment variables
- Optional API layer: RestAssured
- Optional retry and flaky handling: IRetryAnalyzer + rerun suite

4) Branching + Git Strategy
- Branch model:
  - main: production-ready
  - develop: integration branch
  - feature/*: feature or test case implementation
  - hotfix/*: urgent fixes
- Commit style:
  - feat:, fix:, test:, chore:, ci:
- Pull Request rules:
  - At least 1 approval
  - CI checks mandatory (compile + smoke suite)
  - No direct push to main
- Tags:
  - vX.Y.Z for framework releases

5) Maven Dependencies and Plugins (Baseline)
- Dependencies:
  - selenium-java
  - testng
  - webdrivermanager
  - slf4j-api + logback-classic
  - allure-testng
  - jackson-databind (if JSON test data)
- Plugins:
  - maven-surefire-plugin (suite execution, parallel config)
  - maven-compiler-plugin (Java 17)
  - allure-maven
  - maven-failsafe-plugin (if separating integration/e2e)

6) Framework Design Standards
- Page Object Model:
  - Keep locators and page actions in page classes
  - No direct driver operations in test classes
- BaseTest:
  - setup/teardown
  - browser and environment handling
  - thread-safe driver with ThreadLocal
- Wait strategy:
  - explicit waits only; avoid hard sleeps
- Config strategy:
  - priority: CLI param > environment variable > properties file
- Test data strategy:
  - externalized data files (JSON/CSV) under src/test/resources/testdata
- Parallel run:
  - method/class level based on suite needs
  - each thread uses isolated driver instance

7) Test Suite Strategy
- Smoke suite:
  - critical user journeys
  - runs on each PR
- Regression suite:
  - broader functional coverage
  - nightly
- E2E suite:
  - full business flows
  - pre-release or scheduled
- Include test grouping in TestNG:
  - groups = smoke, regression, e2e, sanity

8) CI/CD Blueprint (GitHub Actions)
A) PR Validation Pipeline (pr-validation.yml)
- Trigger: pull_request to develop/main
- Jobs:
  1. checkout
  2. setup-java (Temurin 17)
  3. cache maven repository
  4. mvn clean test -DsuiteXmlFile=testng-smoke.xml
  5. publish Surefire + Allure artifacts
- Gate:
  - PR cannot merge if pipeline fails

B) Nightly Regression Pipeline (nightly-regression.yml)
- Trigger: schedule (cron, e.g., daily 1 AM)
- Jobs:
  1. checkout
  2. setup-java + cache
  3. run regression suite
     mvn clean test -DsuiteXmlFile=testng-regression.xml -Denvironment=qa
  4. upload reports/artifacts
  5. notification to Slack/Teams/Email

C) Release Pipeline (release.yml)
- Trigger: push tag v*
- Jobs:
  1. run smoke + critical regression
  2. package framework artifacts (if needed)
  3. publish release notes and test evidence
  4. mark deployment readiness

9) Sample GitHub Actions Job Skeleton
- Java setup:
  uses: actions/setup-java@v4
  with:
    distribution: temurin
    java-version: '17'
- Execute:
  run: mvn -B clean test -DsuiteXmlFile=testng-smoke.xml
- Artifacts:
  - target/surefire-reports
  - allure-results

10) Secrets and Environment Management
- Store secrets in GitHub Actions Secrets:
  - APP_USERNAME, APP_PASSWORD, BASE_URL, API_TOKEN
- Never commit credentials in code or properties files
- Use environment-specific config files without secrets

11) Quality Gates and Governance
- Mandatory CI status checks on PR
- Retry policy only for known transient issues
- Flaky tests tracked with ownership and SLA
- Execution trend dashboard:
  - pass/fail trend
  - flaky rate
  - duration trend
- Exit criteria:
  - smoke pass required for merge
  - regression pass threshold (example: >= 98%) for release

13) Definition of Done (DoD)
- New test mapped to requirement/user story
- Test added to correct TestNG group
- Local run pass
- CI pass with reports generated
- Page object and utility reuse validated (no duplicate logic)
- Code reviewed and merged through PR

15) Common Run Commands
- Run smoke:
  mvn clean test -DsuiteXmlFile=testng-smoke.xml
- Run regression on QA:
  mvn clean test -DsuiteXmlFile=testng-regression.xml -Denvironment=qa
- Run specific test class:
  mvn -Dtest=LoginTest test
